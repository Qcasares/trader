<objective>
## Goal
Create the async bankr.bot API client (`src/bankr_client.py`) that wraps the prompt/job-polling workflow and exposes typed trade methods.

## Purpose
The bankr.bot client is the bridge between our decision-making agents and actual trade execution. Without it, approved trade signals have no path to market. This is the foundation that the ExecutionAgent (Plan 02-02) will use to submit trades.

## Output
- `src/bankr_client.py` — Async HTTP client with Chain enum, TradeResult dataclass, BankrAPIError exception, and BankrClient class

<acceptance_criteria>

## AC-1: API Key Validation
```gherkin
Given a BankrClient is initialised with an API key
When the key does NOT start with "bk_"
Then a ValueError is raised with a descriptive message
And when the key DOES start with "bk_" initialisation succeeds
```

## AC-2: Prompt Submission
```gherkin
Given a valid BankrClient with an open session
When execute_prompt(prompt) is called
Then a POST request is sent to {BANKR_BASE_URL}/prompt with {"prompt": prompt}
And the X-API-Key header is included
And the returned jobId is used for polling
```

## AC-3: Job Polling
```gherkin
Given a submitted job with a jobId
When _poll_job(job_id) is called
Then it polls GET {BANKR_BASE_URL}/job/{jobId} at POLL_INTERVAL_SECONDS intervals
And returns the job payload when status is "completed"
And raises BankrAPIError when status is "failed" or "cancelled"
And raises BankrAPIError if MAX_POLL_ATTEMPTS is exceeded
```

## AC-4: Dry-Run Safety
```gherkin
Given a BankrClient initialised with dry_run=True (default)
When any prompt is submitted
Then the prompt is prefixed with "[SIMULATION — DO NOT EXECUTE] "
And when dry_run=False the prompt is submitted unmodified
```

## AC-5: Typed Trade Methods
```gherkin
Given a valid BankrClient
When buy(token, amount_usd, chain), sell(token, amount_usd, chain), or any typed method is called
Then it constructs the correct natural-language prompt
And delegates to execute_prompt()
And returns a TradeResult with success, response, job_id, raw_payload
```

## AC-6: Error Handling
```gherkin
Given an API call that returns a non-200 status
When _submit_prompt or _poll_job processes the response
Then a BankrAPIError is raised with the HTTP status and response body
```

## AC-7: Async Context Manager
```gherkin
Given a BankrClient instance
When used with "async with" syntax
Then an aiohttp.ClientSession is created on entry
And the session is closed on exit
```

</acceptance_criteria>

    - Typed methods: get_portfolio, get_balance, get_price, buy, sell, sell_percentage, swap, set_limit_order, set_stop_loss
      - Each constructs a natural-language prompt and calls execute_prompt
      - buy/sell log with logger.info before execution

    **Conventions:**
    - Use logging module (not print)
    - Type hints on all functions
    - Async/await with aiohttp
    - Follow existing dataclass patterns from base.py
