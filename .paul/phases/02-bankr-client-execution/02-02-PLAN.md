## Goal
Create the ExecutionAgent (`src/agents/execution.py`) that receives approved RiskDecisions, constructs natural-language prompts, submits trades via BankrClient, and tracks execution results including slippage.

## Purpose
The ExecutionAgent is the bridge between the decision pipeline (Signal → Risk) and actual trade execution on bankr.bot. Without it, approved trades cannot be submitted. It completes the signal-to-execution flow.

## Output
- `src/agents/execution.py` — ExecutionAgent class with prompt construction, trade submission, fill price extraction, and slippage tracking
- Updated `src/agents/__init__.py` — Export ExecutionAgent and ExecutionResult

## AC-1: Extends BaseAgent Correctly
```gherkin
Given the ExecutionAgent class
When it is instantiated
Then it extends BaseAgent with role=AgentRole.EXECUTION and model="claude-haiku-4-5-20251001"
And it accepts a bankr_api_key parameter for BankrClient
And it implements execute(context) -> AgentResult and system_prompt() -> str
```

## AC-2: Processes Approved RiskDecisions from Context
```gherkin
Given a context dict containing "risk_decisions" (list of RiskDecision dicts)
When execute(context) is called
Then it filters for approved=True decisions only
And skips rejected decisions with a log message
And returns empty results if no approved decisions exist
```

## AC-3: Constructs Correct Natural-Language Prompts
```gherkin
Given an approved RiskDecision with action="buy", ticker="ETH", adjusted_amount_usd=50.0
When a prompt is constructed
Then it produces "Buy $50.00 of ETH on Base" (or appropriate chain)
And for action="sell" it produces "Sell $50.00 of ETH on Base"
And the chain is determined from context or defaults to Base
```

## AC-4: Submits Trades via BankrClient
```gherkin
Given a constructed prompt
When the trade is submitted
Then it uses BankrClient.buy() or BankrClient.sell() typed methods
And wraps the call in try/except for BankrAPIError
And logs success or failure for each trade
```

## AC-5: Tracks Slippage
```gherkin
Given a completed trade with a fill price in the response
When the execution result is built
Then it calculates slippage as abs(fill_price - expected_price) / expected_price
And includes slippage_pct in the ExecutionResult
And if fill price cannot be extracted, slippage is None with a warning
```

## AC-6: Returns Structured ExecutionResult
```gherkin
Given one or more trade executions
When execute() completes
Then it returns AgentResult with data containing a list of ExecutionResult dicts
Each ExecutionResult has: ticker, action, amount_usd, success, job_id, response, slippage_pct, error
And the overall AgentResult.success reflects whether any trades succeeded
```

## AC-7: Graceful Failure Handling
```gherkin
Given a BankrClient call that raises BankrAPIError
When the error is caught
Then the ExecutionResult for that trade has success=False and the error message
And execution continues for remaining approved decisions (no fail-fast)
And the overall AgentResult includes the error in its errors list
```

  <name>Task 1: Create src/agents/execution.py</name>
  <files>src/agents/execution.py</files>
  <action>
    Create the ExecutionAgent following established agent patterns (signal.py, risk.py).

    **ExecutionResult dataclass:**
    - ticker: str
    - action: str ("buy" | "sell")
    - amount_usd: float
    - success: bool
    - job_id: Optional[str]
    - response: str
    - slippage_pct: Optional[float]
    - error: Optional[str]

    **ExecutionAgent(BaseAgent):**
    - __init__(self, api_key: str, bankr_api_key: str, dry_run: bool = True)
      - super().__init__(AgentRole.EXECUTION, "claude-haiku-4-5-20251001", api_key)
      - Store bankr_api_key and dry_run for BankrClient creation
    - system_prompt() -> str
      - Execution specialist prompt: trade submission, fill tracking, slippage monitoring
    - execute(context: dict) -> AgentResult
      - Extract "risk_decisions" from context (list of dicts)
      - Filter for approved=True only
      - Extract "chain" from context, default to Chain.BASE
      - Extract "expected_prices" from context (dict of ticker→price) for slippage calc
      - For each approved decision:
        - Construct prompt using decision's action, ticker, adjusted_amount_usd (or proposed_amount_usd if no adjustment)
        - Create BankrClient with bankr_api_key and dry_run
        - Use async context manager to submit trade via buy()/sell()
        - Extract fill price from response text (best-effort regex parsing)
        - Calculate slippage if expected_price and fill_price available
        - Build ExecutionResult
        - On BankrAPIError: log, create failed ExecutionResult, continue
      - Return AgentResult with list of ExecutionResult dicts

    **Helper methods:**
    - _get_trade_amount(decision_dict) -> float
      - Return adjusted_amount_usd if present, else proposed_amount_usd
    - _extract_fill_price(response: str) -> Optional[float]
      - Best-effort regex to find dollar amounts or price mentions in response text
      - Return None if no price found (with debug log)
    - _calculate_slippage(expected: float, actual: float) -> float
      - abs(actual - expected) / expected * 100
    - _result_to_dict(result: ExecutionResult) -> dict
      - Serialize ExecutionResult to dict for AgentResult.data

    **Conventions:**
    - Follow same import style as signal.py and risk.py
    - Use logging module throughout
    - Type hints on all functions
    - No Claude API calls needed (Haiku model registered but agent logic is deterministic)
