<acceptance_criteria>

## AC-1: Full pipeline executes in dry-run mode
```gherkin
Given all external APIs are mocked (Anthropic, bankr.bot, CoinGecko, social)
When the orchestrator runs one complete cycle in dry-run mode
Then all 6 pipeline agents execute in order (Research → Sentiment → Technical → Signal → Risk → Execution)
And each agent receives context from upstream agents
And the cycle completes without error
```

## AC-2: Context flows correctly through agent handoffs
```gherkin
Given the pipeline executes sequentially
When each agent produces results
Then the context dict accumulates upstream data at each stage
And promoted keys (current_prices, trade_signals, risk_decisions) are available to downstream agents
```

## AC-3: DRY_RUN safety flag is enforced
```gherkin
Given the system starts in dry-run mode (default)
When ExecutionAgent constructs trade prompts
Then each prompt is prefixed with "[DRY RUN]" or equivalent safety marker
And the dry_run flag propagates from CLI through orchestrator to ExecutionAgent
```

## AC-4: Live mode requires double safety gate
```gherkin
Given --live CLI flag is passed
When DRY_RUN env var is NOT set to "false"
Then the system refuses to start and logs an error
And no trades are submitted
```

## AC-5: Risk limits are wired end-to-end
```gherkin
Given the pipeline produces trade signals
When signals reach RiskAgent
Then position sizing, daily loss limit ($200), and confidence threshold (0.55) are enforced
And only approved trades pass to ExecutionAgent
```

## AC-6: Graceful shutdown stops the loop
```gherkin
Given the orchestrator is running
When shutdown() is called (simulating SIGINT/SIGTERM)
Then the current cycle completes
And no new cycles start
And the system exits cleanly
```

## AC-7: Agent failure does not crash pipeline
```gherkin
Given one agent in the pipeline raises an exception
When the orchestrator catches the failure
Then remaining agents still execute with available context
And the failed agent's heartbeat records the error
And the cycle completes with partial results
```
