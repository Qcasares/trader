<acceptance_criteria>

## AC-1: SignalAgent Fusion Logic Produces Correct Scores
```gherkin
Given sentiment_score=0.6, technical direction="bullish" with strength=0.7, and no volume surge
When _compute_fusion() is called with is_anomaly=False
Then combined_score equals 0.40*0.6 + 0.40*0.7 + 0.20*0.0 = 0.52
And confirming_domains is 2 (sentiment + technical both positive)
```

## AC-2: SignalAgent Anomaly Weights Applied Correctly
```gherkin
Given a ticker flagged as anomaly with sentiment_score=0.8, technical_score=0.3
When _compute_fusion() is called with is_anomaly=True
Then weights are 0.10/0.55/0.35 (not 0.40/0.40/0.20)
And combined_score reflects anomaly weights
```

## AC-3: SignalAgent Fallback Signals Enforce Confidence and Confluence
```gherkin
Given fusion data with combined_score=0.20 and confirming_domains=2
When _fallback_signals() is called
Then a "buy" signal is produced with confidence >= 0.55
And given confirming_domains=1, the signal is "hold" regardless of score
```

## AC-4: RiskAgent Position Sizing Scales Linearly by Confidence
```gherkin
Given confidence=0.0
When _compute_position_size() is called
Then amount equals $25.00 (base)
And given confidence=1.0, amount equals $150.00 (max, capped by max_single_trade)
And given confidence=0.5, amount equals $87.50 (midpoint)
```

## AC-5: RiskAgent Rule Enforcement (Daily Loss, Cooldown, Concentration, Stop-Loss)
```gherkin
Given daily_pnl_usd = -200.0 (daily loss limit breached)
When _assess_signal() is called for any buy signal
Then the decision is rejected with reason containing "Daily loss limit"
And given a ticker within cooldown, decision is rejected with "Cooldown"
And given a position exceeding 40% concentration, buy is rejected or reduced
And given a position dropped >8% from entry, stop-loss sell is generated
```

## AC-6: RiskAgent Claude Override Is One-Way (Reject Only)
```gherkin
Given a rule-based rejection (daily loss limit)
When Claude recommends approved=True
Then the final decision remains rejected (Claude cannot override hard limits)
And given a rule-based approval, Claude can downgrade to rejected
And given a rule-based approval, Claude can reduce amount (not increase)
```

## AC-7: ExecutionAgent Filters for Approved Decisions Only
```gherkin
Given risk_decisions with 2 approved and 1 rejected
When ExecutionAgent.execute() is called
Then only 2 trades are submitted to BankrClient
And the rejected decision is logged but not executed
```

## AC-8: BankrClient Dry-Run Prefix and API Key Validation
```gherkin
Given dry_run=True
When _submit_prompt() constructs a prompt
Then the prompt is prefixed with "[SIMULATION — DO NOT EXECUTE]"
And given an API key not starting with "bk_", BankrClient raises ValueError
```

## AC-9: Orchestrator Pipeline Executes Agents in Order with Context Accumulation
```gherkin
Given a mock orchestrator with 6 pipeline agents
When run_cycle() is called
Then agents execute in order: Research → Sentiment → Technical → Signal → Risk → Execution
And each agent's output is merged into the shared context dict
```

## AC-10: Orchestrator Graceful Degradation — Agent Failure Doesn't Crash Pipeline
```gherkin
Given an agent that raises an exception during execute()
When the orchestrator runs the pipeline
Then the failing agent's error is logged but the pipeline continues
And remaining agents still execute with the accumulated context
```
