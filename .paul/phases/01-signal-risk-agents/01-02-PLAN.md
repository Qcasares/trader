<objective>
## Goal
Create the RiskAgent that evaluates trade signals from SignalAgent and enforces position sizing, daily loss limits, cooldown periods, concentration limits, and stop-loss thresholds before any trade can be executed.

## Purpose
The RiskAgent is the final safety gate in the trading pipeline. Without it, raw trade signals would reach execution unchecked — risking overexposure, consecutive losses, and portfolio concentration. Every trade MUST pass through RiskAgent.assess() before dispatch to bankr.bot.

## Output
- `src/agents/risk.py` — RiskAgent class with all risk controls
- Updated `src/agents/__init__.py` — Export RiskAgent and RiskDecision

## AC-1: Position Sizing Based on Confidence
```gherkin
Given a TradeSignal with action "buy" or "sell" and a confidence score
When RiskAgent computes the position size
Then the trade amount scales linearly from base_usd ($25) to max_usd ($150) based on confidence
And the amount never exceeds max_single_trade_usd ($150)
```

## AC-2: Daily Loss Limit Enforcement
```gherkin
Given the portfolio's daily realised P&L from context
When the cumulative daily loss reaches or exceeds max_daily_loss_usd ($200)
Then all subsequent signals are rejected with reason "daily loss limit reached"
And the RiskDecision.approved is False
```

## AC-3: Trade Cooldown Per Ticker
```gherkin
Given a trade signal for ticker X
When a trade for ticker X was executed within the last cooldown_minutes (15 min)
Then the signal is rejected with reason "cooldown active"
And the remaining cooldown time is included in the reason
```

## AC-4: Portfolio Concentration Limit
```gherkin
Given current portfolio positions from context
When a buy signal would cause a single ticker to exceed 40% of total portfolio value
Then the trade amount is reduced to stay within the 40% concentration limit
Or rejected entirely if even the minimum trade ($5) would breach the limit
```

## AC-5: Stop-Loss Flag Detection
```gherkin
Given current portfolio positions with entry prices from context
When any position has dropped by more than stop_loss_pct (8%) from its entry price
Then RiskAgent includes a stop-loss alert in its output
And generates a "sell" RiskDecision for that position regardless of SignalAgent output
```

## AC-6: Claude Sonnet Risk Reasoning
```gherkin
Given all trade signals and risk assessment data
When RiskAgent calls Claude Sonnet for final validation
Then the model receives a structured prompt with signals, portfolio state, and risk metrics
And returns JSON with approval decisions, adjusted amounts, and rationale per ticker
```

## AC-7: Graceful Fallback on Claude Failure
```gherkin
Given Claude API call fails during risk reasoning
When RiskAgent processes trade signals
Then it falls back to rule-based risk assessment using the same thresholds
And logs the fallback event
```

    Create src/agents/risk.py implementing RiskAgent that extends BaseAgent.

    **Data structures (dataclasses):**
    - `RiskDecision`: ticker (str), approved (bool), action (str: "buy"/"sell"/"hold"), proposed_amount_usd (float), adjusted_amount_usd (Optional[float]), reason (str), stop_loss_triggered (bool, default False)

    **Constructor:**
    - `__init__(self, api_key: str, max_daily_loss_usd: float = 200.0, max_single_trade_usd: float = 150.0, cooldown_minutes: int = 15, stop_loss_pct: float = 8.0, max_concentration_pct: float = 0.40, base_position_usd: float = 25.0, max_position_usd: float = 150.0)`
    - Call super with AgentRole.RISK, model "claude-sonnet-4-6", api_key
    - Store AsyncAnthropic client for Claude calls
    - Store all risk parameters as instance variables

    **system_prompt():**
    - Return prompt defining agent as a quantitative risk manager for crypto trading
    - Instruct it to evaluate trade signals against risk limits and return JSON decisions
    - Emphasise capital preservation over profit maximisation

    **execute(context: dict) → AgentResult:**
    Context expected keys:
      - trade_signals — list of TradeSignal dicts from SignalAgent
      - daily_pnl_usd — float, today's realised P&L (default 0.0)
      - recent_trades — dict of {ticker: ISO timestamp} for last trade per ticker
      - portfolio_positions — dict of {ticker: {"value_usd": float, "entry_price": float, "current_price": float, "quantity": float}}
      - portfolio_total_usd — float, total portfolio value

    Processing steps:
    1. Extract context data with safe defaults
    2. Check daily loss limit: if daily_pnl_usd <= -max_daily_loss_usd, reject ALL signals
    3. For each trade_signal:
       a. Skip if action == "hold"
       b. Compute position size: linear scale from base_position_usd to max_position_usd based on confidence. Formula: base + (max - base) * confidence. Cap at max_single_trade_usd
       c. Check cooldown: compare recent_trades[ticker] against cooldown_minutes. If within cooldown, reject with remaining time in reason
       d. Check concentration: if action == "buy", compute (current_position_value + proposed_amount) / (portfolio_total + proposed_amount). If > max_concentration_pct, reduce amount or reject
       e. Minimum trade check: reject if adjusted amount < $5.00
    4. Check stop-losses: for each portfolio_position, if (entry_price - current_price) / entry_price > stop_loss_pct/100, generate a sell RiskDecision for that ticker
    5. Call Claude Sonnet for final reasoning with all decisions and portfolio state
       - Parse JSON response: approved, adjusted_amount, rationale per ticker
       - Claude can downgrade (approve → reject) but NOT upgrade (reject → approve) — risk rules are hard limits
    6. Build list of RiskDecision dataclasses
    7. Return self._build_result(success=True, data={"risk_decisions": [...], "decisions_count": N, "approved_count": N, "rejected_count": N, "stop_loss_alerts": [...]})

    **Claude reasoning method:**
    - `_reason_with_claude(decisions, portfolio_state, daily_pnl)` → tuple[list[RiskDecision], int tokens, Optional[str] error]
    - Build prompt with all pre-computed decisions and portfolio context
    - Claude can add rationale, reduce amounts, or reject — but cannot override hard rejections
    - Parse JSON response, merge with rule-based decisions

    **Rule-based fallback:**
    - `_fallback_decisions(decisions)` → list[RiskDecision]
    - Return the pre-computed rule-based decisions as-is (no Claude enhancement)
    - Log the fallback event

    **Error handling:**
    - If context missing trade_signals → return empty decisions with warning
    - If Claude API fails → fall back to rule-based decisions
    - Log all steps via self._logger

    **Do NOT:**
    - Import or depend on database modules (agents communicate via context dict)
    - Add any execution or bankr.bot logic
    - Create separate utility files — keep all logic in risk.py
    - Read from SQLite or any database (all state comes via context dict)
